## 1. Project Overview

### Architecture Philosophy

- **Modular Monolith**: All modules run as isolated `Module` implementations within a single process (`cmd/mmw`), coordinated by the `mmw/pkg/platform` runner.
- **Clean Architecture / Hexagonal**: Strict separation between Domain logic, Application use cases, and Infrastructure adapters. Dependencies always flow inward.
- **Domain-Driven Design (DDD)**: Business logic resides in Aggregate Roots. State transitions are governed by domain methods that enforce invariants and emit Domain Events.
- **Protocol-First API**: API contracts are defined in Protobuf (`contracts/proto`) and served via **Connect RPC**. Application-layer contracts are auto-generated by a custom `protoc-gen-go-contracts` buf plugin.
- **Event-Driven via Transactional Outbox**: Asynchronous inter-module communication using an outbox table to guarantee atomicity between database writes and event publishing.
- **Architecture Enforcement**: Per-module `arch-go.yml` files + `mmw check arch` CLI command enforce layer boundaries in CI.

### Goals

- Single reusable Go platform library (`mmw/pkg/platform`) for consistent module building.
- Reliable event propagation using outbox + in-memory Watermill bus (GoChannel).
- Seamless integration of multiple domains (`auth`, `todo`) in a single Go workspace.
- Type-safe communication between Go backend and Angular frontend via ConnectRPC.

### Technology Stack

| Concern | Technology |
| :--- | :--- |
| Language | Go 1.26.1 (Go Workspaces) |
| API Framework | Connect RPC + Protocol Buffers |
| Database | PostgreSQL via `pgx/v5` |
| Migrations | Goose (embedded SQL, `pfdbmigrator`) |
| Event Bus | Watermill (GoChannel — in-process) |
| Configuration | Layered TOML + Env vars via `pfconfig.NewContext` |
| Logging | `slog` + `lmittmann/tint` (dev) / JSON (prod) |
| Error Handling | `rotisserie/eris` (structured stack traces) |
| Task Runner | Mise |
| Frontend | Angular 17 / TypeScript |
| Architecture Test | `arch-go` per module + `mmw check arch` CLI |
| Symlink Management | GNU Stow |

## 3. mmw/pkg/platform — The Platform Library

Module path: `github.com/piprim/mmw`. Import alias prefix: `pf`.

### `platform/core` — Module Interface

```go
import pfcore "github.com/piprim/mmw/pkg/platform/core"

type Module interface {
    Start(ctx context.Context) error   // blocks; returns nil on clean shutdown
}
```

All feature modules implement this interface. The compile-time assertion `var _ pfcore.Module = (*Module)(nil)` lives in every module root file.

### `platform/config` — Layered Configuration

```go
import pfconfig "github.com/piprim/mmw/pkg/platform/config"

// Fill a config struct from embedded TOML files + env vars.
err := pfconfig.NewContext(ctx, configFS, envPrefix).Fill(cfg)
```

- Prefers env vars over TOML.
- Supports `mapstructure` tags.
- `pfconfig.Base` embeds the common fields (environment, etc.).
- `pfconfig.Database`, `pfconfig.Server` are reusable sub-structs.

### `platform/pg/uow` — Unit of Work

```go
import pfuow "github.com/piprim/mmw/pkg/platform/pg/uow"

uow := pfuow.New(pool)
uow.WithTransaction(ctx, fn)  // starts a tx, passes it via context
uow.Executor(ctx)             // returns active tx or pool connection
```

Repositories hold a `*pfuow.UnitOfWork` and always call `uow.Executor(ctx)` — they never access the pool directly.

### `platform/db` — StructArgs

```go
import pfdb "github.com/piprim/mmw/pkg/platform/db"

// Reflects db-tagged struct fields into map[string]any for pgx.NamedArgs.
_, err := executor.Exec(ctx, query, pgx.NamedArgs(pfdb.StructArgs(todo.Snapshot())))
```

### `platform/db/outbox` — Events Relay

```go
import pfoutbox "github.com/piprim/mmw/pkg/platform/db/outbox"

relay := pfoutbox.NewEventsRelay(pool, eventBus, logger, "todo.event")
// Started in Module.Start:
g.Go(func() error { relay.Start(gCtx); return nil })
```

Polls the outbox table (`WHERE published_at IS NULL`) and publishes rows to the `SystemEventBus`. Uses `SELECT … FOR UPDATE SKIP LOCKED` for multi-instance safety.

### `platform/events` — SystemEventBus

```go
import pfevents "github.com/piprim/mmw/pkg/platform/events"

rawBus := gochannel.NewGoChannel(...)
eventBus := pfevents.NewWatermillBus(rawBus)
```

Producers receive `pfevents.SystemEventBus` (write side). Modules that need raw subscriptions receive `*gochannel.GoChannel` directly.

### `platform/server` — HTTP Server

```go
import pfserver "github.com/piprim/mmw/pkg/platform/server"

srv := pfserver.NewHTTPServer(pfserver.HTTPServerInfra{
    Config:    cfg.Server,
    Handler:   mux,
    Logger:    infra.Logger,
    HealthFns: pfserver.HealthFns{"database": repo.Health},
})
```

- Built-in `GET /debug/monit` health endpoint (JSON).
- Development-only `/debug/pprof` and gRPC reflection routes (when `Config.DebugEnabled`).
- Middleware chain: Logging → Recovery → CORS → Application mux.
- Uses `h2c` for HTTP/2 cleartext (required for Connect RPC).

### `platform/middleware` — Auth Middleware

```go
import pfmiddleware "github.com/piprim/mmw/pkg/platform/middleware"

// TokenValidator is a function type: validates a bearer token → user UUID.
type TokenValidator func(ctx context.Context, token string) (uuid.UUID, error)

// NewAuth wraps an http.Handler with JWT validation.
authMiddleware := pfmiddleware.NewAuth(tokenValidator, logger)
mux.Handle(path, authMiddleware(connectHandler))
```

### `platform/slog` — Structured Logging

```go
import pfslog "github.com/piprim/mmw/pkg/platform/slog"

logger, err := pfslog.New(pfslog.HandlerText, logLevel) // dev: colorized tint
logger, err := pfslog.New(pfslog.HandlerJson, logLevel)  // prod: JSON
```

`erisPostPrintHandler` wraps the underlying handler to print `eris` stack traces after the log line.

### `platform/connect` — Interceptors

```go
import pfconnect "github.com/piprim/mmw/pkg/platform/connect"

connect.WithInterceptors(pfconnect.NewErrorLoggingInterceptor(logger))
```

### `platform/runner` — App Runner

```go
import "github.com/piprim/mmw/pkg/platform"

platform.New(logger, modules).Run(ctx)
```

Runs all modules in a shared-fate `errgroup`. Any module failure cancels the shared context, triggering graceful shutdown of all other modules.

## 5. contracts — Protobuf + Generated Code

### Two-Level Generation

```
contracts/proto/<domain>/v1/<domain>.proto
         │
         ├── buf.build/protocolbuffers/go   → go/network/<domain>/v1/*.pb.go
         ├── buf.build/connectrpc/go        → go/network/<domain>/v1/<domain>v1connect/
         └── protoc-gen-go-contracts        → go/application/<domain>/
                 ├── *_contract_gen.go      ← Service interface + NoopXxxService
                 ├── events_gen.go          ← TopicXxx constants + Topics slice + type aliases
                 └── errors_gen.go          ← ErrorCodeXxx constants (proto enum aliases)
```

TypeScript stubs are also generated into `ts/` (from `buf.build/connectrpc/es`) for the Angular frontend.

### Generating

```bash
cd poc/contracts

# 1. Build custom plugin (once):
go build -o $(go env GOPATH)/bin/protoc-gen-go-contracts ./cmd/protoc-gen-go-contracts

# 2. Standard plugins (network layer):
buf generate --template buf.gen.todo.yaml
buf generate --template buf.gen.auth.yaml

# 3. Custom plugin (application layer):
buf generate --template buf.gen.yaml
```

### Contract Package Invariants

- `contracts/go/application/` packages depend **only** on `connectrpc/connect` and `google.golang.org/protobuf`.
- No feature module may be imported by a contract package (structurally impossible — circular module dependency).
- `connect_client.go` is hand-written (not regenerated) — it wraps the Connect transport as the contract interface.

## 6. modules/auth — Authentication & Identity

Module path: `github.com/pivaldi/mmw-auth`

### API (`auth.v1`)

| RPC | Description |
| :--- | :--- |
| `Register` | Creates a new user, emits `UserRegistered` event |
| `Login` | Returns a signed JWT token |
| `ValidateToken` | Verifies JWT and returns `user_id` (private service) |
| `ChangePassword` | Updates hashed password |
| `DeleteUser` | Removes user and emits `UserDeleted` event |

### Module Accessors

```go
// auth.go — exposed for the composition root
func (m *Module) PrivateService() authdef.AuthPrivateService { ... }
func (m *Module) PublicService()  authdef.AuthPublicService  { ... }
```

Both return `inproc.NewContractAdapter(m.service)`, a `ContractAdapter` that implements the generated contract interface by translating proto-typed requests to the internal DTO-based application service.

### Cross-Module Integration

The `todo` module receives `defauth.AuthPrivateService` via its `Infrastructure.AuthSvc` field. In the monolith this is satisfied by `authModule.PrivateService()` (in-process, zero network overhead). To split auth into a separate process, replace it in the composition root with `defauth.NewPrivateHTTPClient(connectClient)` — no application code changes required.

### Events Emitted

Topic constants from `contracts/go/application/auth/events_gen.go`:
- `TopicUserRegistered` = `"auth.user.registered.v1"`
- `TopicUserDeleted` = `"auth.user.deleted.v1"`
- `TopicPasswordChanged` = `"auth.user.password_changed.v1"`
- `TopicUserLoggedIn` = `"auth.user.logged_in.v1"`

## 7. modules/todo — Domain Service

Module path: `github.com/pivaldi/mmw-todo`

### Domain

`Todo` aggregate root manages state transitions via explicit business methods:
- `NewTodo(title, description, priority, dueDate, userID)` → emits `TodoCreated`
- `Complete()` → emits `TodoCompleted`; returns `ErrCannotCompleteCancelled` if cancelled
- `Reopen()` → emits `TodoReopened`; idempotent if already open
- `Cancel()`, `MarkInProgress()`, `Update(…)` → emit `TodoUpdated`

Value objects: `TodoID` (UUID string wrapper), `TaskTitle` (1–200 chars), `TaskStatus` (go-enum), `Priority` (go-enum), `DueDate` (must be in the future).

`TodoSnapshot` uses `db` struct tags for `pgx.RowToStructByName` scanning.

### Application Layer

`TodoService` (primary port, internal interface — not the generated contract):
```go
// internal/application/service.go
type TodoService interface {
    CreateTodo(ctx, *dto.CreateTodoRequest) (*dto.TodoResponse, error)
    GetTodo(ctx, id string) (*dto.TodoResponse, error)
    UpdateTodo(ctx, id string, *dto.UpdateTodoRequest) (*dto.TodoResponse, error)
    CompleteTodo(ctx, id string) (*dto.TodoResponse, error)
    ReopenTodo(ctx, id string) (*dto.TodoResponse, error)
    DeleteTodo(ctx, id string) error
    ListTodos(ctx, *dto.ListFilters) (*dto.ListTodosResponse, error)
    Health(ctx) (any, error)
}
```

`TodoApplicationService` delegates to command and query handlers. Commands use `uow.WithTransaction`; queries use direct repository reads with no transaction.

### Inbound Adapters

**Connect handler** (`adapters/inbound/connect/todo_handler.go`): bridges Connect HTTP requests to the internal `application.TodoService`. Maps proto enums ↔ domain enums; calls `connectErrorFrom(err)` for error translation.

**ContractAdapter** (`adapters/inbound/inproc/contract_adapter.go`): implements `tododef.TodoService` (the generated contract interface) by wrapping the internal application service. Used for in-process calls.

**Event handler** (`adapters/inbound/events/auth_handler.go`): Watermill handler reacting to `defauth.TopicUserDeleted` — deletes all tasks for the removed user.

**Error mapper** (`adapters/inbound/mapper/errors.go`): maps domain sentinel errors (`ErrTodoNotFound`, etc.) to `platform.DomainError` with proto error codes from `contracts/go/application/todo/errors_gen.go`.

### Outbound Adapters

**Repository** (`adapters/outbound/persistence/postgres/todo_repository.go`):
- Accepts `*pfuow.UnitOfWork`; never a raw pool.
- Writes: `pgx.NamedArgs(pfdb.StructArgs(todo.Snapshot()))` — named args from `db`-tagged snapshot fields.
- Reads: `pgx.CollectOneRow(rows, pgx.RowToStructByName[domain.TodoSnapshot])`.

**Outbox dispatcher** (`adapters/outbound/events/outbox_dispatcher.go`):
- Writes to `todo.event` in a pgx batch inside the active UoW transaction.
- `domainTopics` map (in `topics.go`) translates domain event type strings → Watermill routing keys (contract topic constants).
- Events serialized as protojson where a proto message exists; falls back to `json.Marshal`.

### Events Emitted

Topic constants from `contracts/go/application/todo/events_gen.go`:
- `TopicUserTaskCreated`, `TopicUserTaskUpdated`, `TopicUserTaskCompleted`
- `TopicUserTaskReopened`, `TopicUserTaskDeleted`, `TopicUserTasksDeleted`

### Authentication

All RPCs are protected by `pfmiddleware.NewAuth(tokenValidator, logger)`. The `tokenValidator` is built by `NewTokenValidator(svc defauth.AuthPrivateService)` which calls `svc.ValidateToken` and parses the user UUID from the response.

The authenticated user UUID is stored in the request context via `pfmiddleware` and retrieved in command handlers via `appctx.UserID(ctx)`.

## 8. modules/notifications — Event Consumer

Module path: `github.com/pivaldi/mmw-notifications`

A reactive module with no domain logic. It subscribes to every topic in its `Infrastructure.Topics` slice (passed from the composition root as `append(tododef.Topics, authdef.Topics...)`).

For each topic it starts a goroutine (inside a shared errgroup) that reads from the Watermill `message.Subscriber` channel, logs the event, and optionally dispatches a RocketChat notification (configurable via `ROCKET_HOST`, `ROCKET_USER`, `ROCKET_KEY` env vars).

The notifications module receives the raw `*gochannel.GoChannel` as `message.Subscriber` — not the wrapped `SystemEventBus`.

## 10. Cross-Cutting Concerns

### Error Handling

- Use `rotisserie/eris` throughout: `eris.Wrap(err, "context")`, `eris.Wrapf(err, "context %s", val)`.
- `pfconnect.NewErrorLoggingInterceptor(logger)` logs RPC failures with `eris` stack traces.
- Map domain sentinels → `platform.DomainError` in `adapters/inbound/mapper/errors.go`.
- Map `platform.DomainError` → Connect status codes in `adapters/inbound/connect/errors.go` using the `domainConnectCodeMap` table + a typed `commonv1.DomainError` proto detail.
- **Rule**: No cross-module imports (except via `contracts/go/application/` interfaces or `pfmiddleware`).

### Architecture Testing

Each module has an `arch-go.yml` defining allowed import dependencies for each layer.

The `mmw check arch` CLI command (`mmw/cmd/mmw/`) runs `archtest.RunAll`, which:
1. Discovers all modules with a `mise arch:check` task.
2. Runs `arch-go` in each module directory.
3. Aggregates and prints a pass/fail summary.

Run it via:
```bash
cd poc
go run ./mmw/cmd/mmw check arch
```

### Logging

```go
// Module-scoped logger — passed through Infrastructure.Logger
logger := baseLogger.With("module", auth.ModuleName)

// Usage in handlers/commands
slog.InfoContext(ctx, "todo created",
    slog.String("todo_id", todo.ID().String()),
    slog.String("user_id", userID.String()),
)
```

`pfslog` provides `HandlerText` (colorized `tint`, dev) and `HandlerJson` (prod). The `erisPostPrintHandler` wrapper prints `eris` stack traces below the log line.

## 11. Event-Driven Architecture

### Transactional Outbox (step by step)

1. **Command handler** calls `uow.WithTransaction(ctx, fn)`.
2. Inside `fn`: repository saves the Aggregate (e.g. `INSERT INTO todo.todo`) **and** the dispatcher writes events to the outbox table (`INSERT INTO todo.event`) — same transaction, atomic commit.
3. Background **`EventsRelay`** (started in `Module.Start`) polls `todo.event WHERE published_at IS NULL ORDER BY occurred_at ASC` and publishes each row to the `SystemEventBus`.
4. **Watermill subscribers** (event router in `todo`, the notifications module) receive messages and process them.

### Topic Mapping

Domain event type strings (`"todo.created"`) are semantic identifiers owned by the domain layer. The outbound adapter's `domainTopics` map translates them to Watermill routing keys (contract topic constants like `tododef.TopicUserTaskCreated = "todo.userTasks.created.v1"`). This is the **single translation point** — domain code never references contract constants.

### Guarantees

| Property | Detail |
| :--- | :--- |
| At-least-once delivery | Crash between `Publish` and `UPDATE` causes relay to retry. Consumers must be idempotent. |
| Ordering | Rows fetched `ORDER BY occurred_at ASC` — preserves intra-aggregate event order. |
| Latency | Up to 2 s between domain write and bus publication (relay poll interval). |
| Multi-instance safe | `SELECT … FOR UPDATE SKIP LOCKED` prevents duplicate processing. |

## 12. Developer Guide

### Running the Monolith

```bash
cd poc
go run ./cmd/mmw
```

### Generating Contracts After Proto Changes

```bash
cd poc/contracts
go build -o $(go env GOPATH)/bin/protoc-gen-go-contracts ./cmd/protoc-gen-go-contracts
buf generate --template buf.gen.todo.yaml
buf generate --template buf.gen.auth.yaml
buf generate --template buf.gen.yaml
```

### Adding a New RPC

1. Edit `contracts/proto/<module>/v1/<module>.proto`.
2. Run `buf generate` (all three templates).
3. Implement the method on `TodoHandler` in `internal/adapters/inbound/connect/`.
4. Implement the method on `ContractAdapter` in `internal/adapters/inbound/inproc/`.
5. Update `application.TodoService` interface and `TodoApplicationService`.
6. Add/update command or query handler under `application/command/` or `application/query/`.

### Running Architecture Tests

```bash
cd poc
go run ./mmw/cmd/mmw check arch
```

### Adding a New Module

```bash
cd poc/mmw

```
